# Submission checklist

## Before recording

- [ ] Install from `requirements.lock` in the recording environment.
- [ ] Run the full tests and `python -m compileall policygate`.
- [ ] Confirm `.env`, `.vscode/mcp.json`, `terraform/`, `*.tfstate*`, and `tfplan` are ignored/untracked.
- [ ] Use a dedicated AWS sandbox account/role with least privilege.
- [ ] Set live Claude credentials and keep `POLICYGATE_ALLOW_AI_FALLBACK=false`.
- [ ] Configure Foxit PDF/MCP credentials in the external MCP host.
- [ ] Configure live Foxit eSign credentials.
- [ ] If using webhooks, configure a Foxit webhook secret and verify the raw-body HMAC signature.
- [ ] Set `POLICYGATE_INCLUDE_TERRAFORM_PLAN=true`.
- [ ] Choose exactly one real human signing route: `POLICYGATE_FOXIT_SEND_NOW=true` **or** `POLICYGATE_EMBEDDED_SIGNING=true`.
- [ ] Set `POLICYGATE_SUBMISSION_MODE=true` for the final recorded run.
- [ ] Keep `POLICYGATE_ALLOW_APPLY=false` unless deliberately demonstrating billable provisioning.
- [ ] Keep `POLICYGATE_ALLOW_DESTROY=false` except during intentional cleanup.

## Demo proof to capture

- [ ] UI badges show Claude LIVE, Foxit eSign LIVE, Terraform LIVE PLAN.
- [ ] Plain-English request and Claude structured intent.
- [ ] Policy-injected controls versus explicitly requested controls.
- [ ] PASS checks for the compliant request and a BLOCKED unsafe request.
- [ ] Real Terraform plan summary.
- [ ] Exact `tfplan` SHA-256 displayed in UI and approval PDF.
- [ ] One genuine Foxit PDF/MCP tool invocation/result in the MCP host.
- [ ] Real Foxit eSign human signing screen.
- [ ] `AWAITING_HUMAN_APPROVAL` hard stop.
- [ ] `policygate-complete` shows same folder, `EXECUTED`, and verified signer email; if using webhook finalization, show/verify `folder_executed`.
- [ ] Final audit contains signed-PDF hash and `APPROVED`.

## AWS/Terraform safety

- [ ] Generated HCL uses `manage_master_user_password = true`; no DB password is generated by PolicyGate.
- [ ] No Terraform state or saved plan is committed or copied into submission screenshots.
- [ ] If apply is demonstrated, verify the signed audit contains `terraform_plan_file_sha256` and the existing `tfplan` hash matches.
- [ ] If cleanup is needed, set `POLICYGATE_ALLOW_DESTROY=true` only temporarily and pass `--confirm-request-id` with the exact request ID.

## Repository hygiene

- [ ] Remove `.git/` from uploaded ZIP/TAR packages (keep it only in the actual GitHub repo).
- [ ] `.env.example` contains placeholders only.
- [ ] GitHub Actions is green.
- [ ] README screenshots show no credentials, private emails, signed session URLs, state, or secret values.
- [ ] Add 2–4 screenshots: guardrails, Terraform hash, approval PDF, human-stop screen.
- [ ] Add public repository and demo-video URLs.
- [ ] Tag the final release.
- [ ] Confirm no employer-confidential material is present.

## Submission copy

- [ ] Update `docs/DEVPOST_SUBMISSION.md` to match only the integrations actually demonstrated.
- [ ] Name Foxit prominently and explain the MCP/eSign roles separately.
- [ ] Emphasize that the human approves the exact Terraform plan artifact, not a model-generated summary.
- [ ] Re-check the official challenge page and deadline immediately before submitting.
